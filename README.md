# zapret2-slipstream

Автоподбор рабочих стратегий противодействия DPI для [zapret2](https://github.com/bol-van/zapret2): скрипт гоняет штатный `blockcheck2` по TLS 1.3, TLS 1.2 и QUIC, выбирает рабочие стратегии (для TLS — по возможности **общую** для 1.2 и 1.3), собирает `NFQWS2_OPT`, аккуратно вносит его в конфиг с бэкапом, перезапускает сервис и присылает отчёт в Telegram.

> **Важно об авторстве.** Всю тяжёлую работу по противодействию DPI делает [zapret2](https://github.com/bol-van/zapret2) за авторством **bol-van** — это его движок (`nfqws2`) и его инструмент перебора (`blockcheck2`). Данный скрипт **ничего не изобретает** в части противодействия: он лишь автоматизирует запуск `blockcheck2`, разбор его вывода и применение результата. Это надстройка-обёртка, а не замена zapret2. Если zapret2 вам полезен — поблагодарите его автора, а не этот скрипт.

---

## Что он делает

- Останавливает `zapret2`, чистит conntrack и запускает `blockcheck2` последовательно по трём протоколам: **TLS 1.3 → TLS 1.2 → QUIC**.
- Собирает список рабочих стратегий по каждому протоколу.
- Для TLS выбирает стратегию по приоритету:
  1. **общая** — работает и для 1.3, и для 1.2 (максимум совместимости);
  2. если общей нет — первая рабочая для 1.3;
  3. если и 1.3 нет — первая рабочая для 1.2.
  (В `nfqws2` TLS-профиль один и не делится по версии фильтром, поэтому «общая» — это лучший вариант «одним профилем покрыть обе версии».)
- Собирает `NFQWS2_OPT` (HTTP + TLS + QUIC профили), делает бэкап текущего конфига и вносит новый.
- Перезапускает `zapret2`, делает контрольную проверку доступности.
- Шлёт подробный отчёт в Telegram (через SOCKS5, т.к. Telegram у многих провайдеров блокируется): применённые стратегии, статистику находок, диагностику по TLS 1.2, запасные стратегии и готовый **запасной `NFQWS2_OPT`** на случай, если основной вариант перестанет работать.

## Ключевые особенности

- **Безопасность конфига.** Если ничего не найдено — конфиг **не трогается**, прежняя рабочая стратегия сохраняется. Если найдена только одна из стратегий (TLS или QUIC) — для второй подставляется прежняя из `.current-strat`. Запись идёт с валидацией и откатом на бэкап при сбое. Прерывание по Ctrl+C безопасно (в т.ч. при запуске через `| tee`): blockcheck2 и его следы убираются, `zapret2` поднимается обратно до любого вывода. На любом другом пути выхода — ошибка, `exit 1` из проверок — сервис тоже поднимается, если его останавливал скрипт.
- **Учёт «мягкого» DPI.** Если blockcheck2 сообщает, что трафик проходит и напрямую — скрипт понимает это и не портит конфиг.
- **Гибкие лимиты.** Можно задать, сколько рабочих стратегий собирать и сколько ждать (см. параметры).
- **Диагностика TLS 1.2.** Отдельно проверяет, покрывает ли выбранная стратегия TLS 1.2, и честно предупреждает, если нет.
- **Несколько доменов.** В `DOMAINS` можно перечислить несколько хостов — тогда берутся только стратегии, рабочие для **всех** (см. [Несколько доменов](#несколько-доменов)).
- **Зачистка за blockcheck2.** После каждого прогона (и при прерывании) принудительно снимаются следы blockcheck2: nft-таблицы `blockcheck*`, iptables-цепочки `blockcheck_*`, сиротские процессы `nfqws2`/`tpws2`. Без этого прерванный по таймауту blockcheck оставлял живой `nfqws2` с тестовой стратегией и правила, заворачивавшие в него трафик поверх штатного zapret2.

## Требования

- ОС с systemd (тестировалось на Armbian/Debian, aarch64).
- Установленный и настроенный [zapret2](https://github.com/bol-van/zapret2) с `blockcheck2.sh` и конфигом в каталоге (по умолчанию `/opt/zapret2`).
- POSIX-совместимый `/bin/sh`, `curl`, `conntrack`.
- (Опционально) Telegram-бот и SOCKS5-прокси для уведомлений.

## Про фильтрацию по протоколу (важно)

Скрипт собирает `NFQWS2_OPT` с фильтрами **только по протоколу** (`--filter-tcp=443 --filter-l7=tls` и т.п.), без списков доменов (`--hostlist`). Стратегия применяется ко **всему** TLS/QUIC/HTTP-трафику.

**Почему так.** Скрипт изначально писался под конкретный сценарий — **шлюз, на который приходит только уже отфильтрованный, нужный трафик**. В такой схеме разделять по доменам внутри самого zapret2 незачем: фильтрация делается раньше (маршрутизацией/файрволом выше по цепочке), а до zapret2 доходит лишь тот трафик, который и надо обрабатывать. Поэтому обработка «по протоколу, ко всему» здесь не недостаток, а осознанное упрощение под задачу.

> ⚠️ **Если у вас другая схема.** Когда zapret2 стоит не на выделенном шлюзе, а на машине с обычным трафиком, и настроена фильтрация по доменам (hostlist) — запуск скрипта **перезапишет** её на «применять ко всему по протоколу». Если вам нужна доменная фильтрация — этот скрипт в текущем виде не подойдёт (или потребует доработки под hostlist).

## Установка

```sh
sudo cp zapret2-slipstream.sh /usr/local/bin/
sudo chmod +x /usr/local/bin/zapret2-slipstream.sh
```

При первом запуске скрипт сам создаст каталог и файл настроек `/etc/zapret2-slipstream/.env` с дефолтами.

## Использование

```sh
sudo zapret2-slipstream.sh                 # дефолт: до 3 находок, таймаут 5 мин на прогон, scan-level force
sudo zapret2-slipstream.sh --dry           # показать результат, НЕ трогая конфиг
sudo zapret2-slipstream.sh --dry --no-tg   # тихий тест без уведомлений в Telegram
```

Скрипт рассчитан на **ручной запуск** — когда старая стратегия перестала работать и надо подобрать новую. Можно и в cron (`--cron`), но помните: во время подбора `zapret2` остановлен, и противодействия DPI временно нет (трафик идёт напрямую).

### Параметры

| Параметр | Описание |
|---|---|
| `--dry` | Показать найденный `NFQWS2_OPT`, но не вносить в конфиг и не перезапускать сервис. |
| `--cron` | Тихий режим для crontab: вывод в лог-файл, статус — в Telegram. |
| `--want-tls N` | Сколько рабочих TLS-стратегий собрать до обрыва. `0` — полный перебор (может быть очень долго при мягком DPI). По умолчанию `3`. При нескольких доменах в `DOMAINS` — первый домен набирает `2N`, остальные — `N` общих; для нескольких доменов дефолт мал, см. [Несколько доменов](#несколько-доменов). |
| `--want-quic N` | То же для QUIC. `1` — оборвать на первой найденной. По умолчанию `3`. |
| `--timeout-tls СЕК` | Таймаут на каждый TLS-прогон (1.3 и 1.2 отдельно), при нескольких доменах — на каждый домен. `0` — без таймаута. По умолчанию `300`. |
| `--timeout-quic СЕК` | Таймаут на QUIC-прогон. `0` — без таймаута. По умолчанию `300`. |
| `--scan-level УРОВЕНЬ` | Глубина перебора blockcheck: `quick` / `standard` / `force`. По умолчанию `force` — только в нём пересечения (общая 1.2+1.3, несколько доменов) достоверны, см. врезку ниже. `standard` быстрее при полном переборе (`--want-* 0`), но списки несопоставимы. |
| `--env ПУТЬ` | Прочитать доп. env-файл поверх дефолтного (переопределяет переменные). Если файла нет — создаётся. |
| `--no-tg` | Не слать уведомления в Telegram для этого запуска. |
| `-h`, `--help` | Показать встроенную справку. |

### Примеры

```sh
# больше находок → выше шанс найти общую 1.2+1.3 стратегию (но дольше)
sudo zapret2-slipstream.sh --want-tls 20

# самый быстрый прогон: берём первые же найденные
sudo zapret2-slipstream.sh --want-tls 1 --want-quic 1

# полный перебор TLS, но со страховочным таймаутом 15 мин
sudo zapret2-slipstream.sh --want-tls 0 --timeout-tls 900

# полный перебор всего (долго!)
sudo zapret2-slipstream.sh --want-tls 0 --want-quic 0

# быстрее, но пересечения (общая 1.2+1.3, несколько доменов) ненадёжны
sudo zapret2-slipstream.sh --scan-level standard

# доп. настройки поверх дефолтных
sudo zapret2-slipstream.sh --env /home/user/my.env

# несколько доменов в .env (DOMAINS="www.youtube.com manifest.googlevideo.com"):
# дефолтного --want-tls 3 мало, см. раздел «Несколько доменов»
sudo zapret2-slipstream.sh --want-tls 10 --timeout-tls 900
```

## Настройка (env-файл)

Дефолтный путь: `/etc/zapret2-slipstream/.env` (создаётся автоматически). Переопределить путь можно переменной окружения `AUTOSTRAT_ENV=...` перед запуском.

Порядок применения настроек: **дефолты в скрипте → дефолтный `.env` → файл из `--env`**.

```sh
# --- Telegram (пусто = уведомления выключены) ---
BOT_ID=""
CHAT_ID=""
# SOCKS5 для отправки в Telegram (host:port или user:pass@host:port).
# Нужен, если Telegram у вашего провайдера заблокирован: укажите прокси,
# через который Telegram доступен. Если Telegram открывается напрямую — оставьте пустым.
SOCKS5=""

# --- пути и цель ---
ZAPRET_DIR="/opt/zapret2"
SERVICE="zapret2"
# Домен(ы) для blockcheck через пробел. По умолчанию один; про несколько — см. раздел ниже.
DOMAINS="www.youtube.com"
LOGFILE="/var/log/zapret2-slipstream.log"
# Сырые логи blockcheck2 (bc-tls13.log, bc-tls12.log, bc-quic.log) после прогона.
# Пусто — не сохранять. Предыдущие — с суффиксом .prev.
BC_LOG_DIR="/var/lib/zapret2-slipstream"
```

Лимиты (`--want-*`, `--timeout-*`) в `.env` не выносятся — они управляются флагами.

> 💡 **Сырые логи blockcheck2** сохраняются в `BC_LOG_DIR` после каждого прогона — и в `--dry`, и в боевом. В них то, чего нет в выводе скрипта: диагностика IP-блокировок (`IP block tests`), проверка DNS, полный список протестированных стратегий с вердиктами. Без них вопрос «почему для этого домена QUIC не нашёлся — по IP режут или по SNI?» упирается в повторный запуск на десять минут. На Armbian `/var/log` часто в zram и стирается при перезагрузке — поэтому дефолт `/var/lib/…`, а не `/var/log/…`.

> ℹ️ **Про глубину перебора.** Дефолт скрипта — `--scan-level force`, и это не то же, что «полный перебор»: обрыв по `--want-*` работает как обычно, порядок стратегий тот же, что в `standard`, просто blockcheck не пропускает группы. Пропуски — вот в чём проблема `standard`: blockcheck решает, что тестировать дальше, по результатам предыдущих стратегий, а результаты для TLS 1.2 и 1.3 (и для разных доменов) разные. Списки получаются **несопоставимыми**: стратегия может отсутствовать в списке 1.2 не потому, что не работает, а потому что её там не тестировали — и «общая» не находится. Сам blockcheck пишет о своём `COMMON` то же самое. `standard` имеет смысл, когда нужен быстрый полный перебор (`--want-* 0`) и общая стратегия не важна.

> Формат файла: `VAR="значение"`. Комментарии — только отдельной строкой (`# ...`), **не** в конце строки со значением.

## Несколько доменов

В `DOMAINS` можно указать несколько хостов через пробел. Зачем: YouTube ходит в два разных места — `www.youtube.com` / `youtubei.googleapis.com` за API и страницами и `*.googlevideo.com` за самим видео, и DPI может относиться к ним по-разному. Стратегия, подобранная только против главной страницы, не обязана пробивать CDN.

**Рекомендуемая пара:**

```sh
DOMAINS="www.youtube.com manifest.googlevideo.com"
```

`manifest.googlevideo.com` — стабильный служебный хост CDN: живёт годами, всегда резолвится, отвечает по HTTPS (404 — для blockcheck это нормальный ответ) и говорит HTTP/3, поэтому годится и для QUIC-теста. `redirector.googlevideo.com` для QUIC-теста **не годится** — по HTTP/3 не отвечает. Реальные `rrN---sn-*.googlevideo.com`, с которых идут сегменты, меняются и в `.env` не приживутся. Проверить кандидата перед добавлением:

```sh
curl -sS -I --http3-only https://manifest.googlevideo.com/ | head -1   # ожидается HTTP/3 404
```

**Как это работает.** blockcheck2 запускается на каждый домен отдельно и последовательно, у каждого — свой таймаут (`--timeout-*`) и свой обрыв по количеству. В результат попадают только стратегии, рабочие для **всех** доменов; домены, которые проходят напрямую, и домены с `test aborted` (не резолвится, недоступен) из пересечения исключаются — они ничего не ограничивают. Первый домен набирает `--want-* × 2` находок (запас, из которого следующим будет с чем пересекаться), остальные обрываются, когда общих набралось `--want-*`. Общее время подбора растёт пропорционально числу доменов.

> ⚠️ **Риск: маленькие `--want-*` с несколькими доменами.** Каждый список рабочих стратегий — уже пересечение по доменам, он короче. А общая для TLS 1.2+1.3 ищется как пересечение **двух** таких списков. С дефолтным `--want-tls 3` это пересечение двух троек — оно легко оказывается пустым, даже если общая стратегия существует пятой по счёту. Скрипт тогда честно возьмёт «только 1.3», но это хуже, чем могло быть. Поэтому для нескольких доменов:
>
> - `--want-tls 8`–`10` или `--want-tls 0` с разумным `--timeout-tls`;
> - не переключаться на `--scan-level standard`: в нём blockcheck пропускает часть стратегий, и пересечение не найдёт то, что просто не было протестировано;
> - если один из доменов так и не появился в тесте (таймаут, не резолвится) — скрипт предупредит строкой `!!! домен … в тесте не появился — результат получен БЕЗ него`. Это не ошибка, но результат получен не по тому набору, который вы задали.

Один домен в `DOMAINS` — поведение прежнее, без пересечений и удвоенных порогов.

## Поведение при разных результатах

| Ситуация | Что делает скрипт |
|---|---|
| Нашлись стратегии для TLS и QUIC | Собирает и применяет новый конфиг |
| Нашлась только одна из двух | Для второй берёт прежнюю из `.current-strat` |
| Оба протокола проходят «напрямую» | Конфиг **не трогает** (блокировка временно снята) |
| Ничего не найдено | Конфиг **не трогает**, прежняя стратегия сохраняется |
